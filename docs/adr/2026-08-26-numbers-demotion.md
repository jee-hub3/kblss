# ADR: KBLs in Numbers를 히어로 직후에서 서사 4장('완주한다')으로 하향

- 날짜: 2026-08-26
- 상태: 승인(오너 지시) — 머지 승인 대기 PR에 포함
- 뒤집는 결정: "성과 지표 블록을 히어로 직후로 상향(성과 선노출)" — 커밋 271d347, PR #18(디자인 P1), 2026-08-24
- ※ 오너 측 ADR 대장(ADR-11이 존재)이 저장소 밖에 있어, 이 문서는 저장소 사본이다. 대장에 옮길 때 번호를 부여할 것.

## 배경

홈 7개 섹션이 각각 "우리는 이렇습니다"를 병렬로 설명해 순서를 바꿔도 말이 됐다 —
즉 서사가 없었다. 2026-08-26 오너 지시로 홈을 5장 서사로 재배치한다:
① 문제를 만난다(Hero) → ② 팀이 된다(Identity·Bridge) → ③ 만든다(What We Do·Featured)
→ ④ 완주한다(Numbers) → ⑤ 다음은 당신 차례(Fit + CTA 병합).

## 결정

Numbers를 2번째 섹션(히어로 직후)에서 6번째 섹션(Featured 다음)으로 내린다.

## 이유

맥락 없는 숫자는 "그래서 뭐"가 된다. 팀(②)과 활동·산출물(③)을 본 뒤에는
같은 숫자("완주율 90%")가 결론으로 읽힌다 — KBLs의 지표가 완주율이라는
정체성과도 서사 위치가 일치한다.

## 기존 결정의 근거 조사 (뒤집기 전 확인)

- 커밋 271d347·PR #18: 근거는 "성과 선노출"(P1 디자인 항목) 그 자체. 추가 논거 없음.
- PR #18 검증 기록: "LCP 요소는 지표 상향 후에도 히어로 문단 유지" — 순서를
  되돌려도 LCP에 영향이 없음을 시사한다(실측으로 재확인함).
- docs/OPERATIONS.md · UX 점검 보고서(2026-08-25, 29건): 섹션 순서 언급 없음.
- 노션(통합 키 접근 범위): 관련 문서 없음.
→ 오너가 모르는 추가 근거는 발견되지 않아 진행한다.

## 파생 조치 (순서에 묶여 있던 것들)

1. **peek 장치(pt-12)**: Numbers → Identity로 이관. 히어로 다음 섹션의 상단
   패딩 48px 고정은 false bottom 방지 장치라 "2번째 섹션"을 따라간다.
2. **배경**: 당초 섹션별 그라데이션 체인을 새 순서로 재연결했으나, 오너 후속
   지시("배경이 이어지지 않는 느낌")로 **홈 전체 단일 연속 그라디언트**
   (`.home-flow-bg`, index.css)로 교체 — 섹션 배경은 전부 투명이 됐다.
   색 이야기는 동일(slate-50 → white → blue·indigo 힌트 → brand-50)하되
   이음새가 원천적으로 없고, 이후 섹션 순서가 또 바뀌어도 배경은 손댈
   필요가 없다.
3. **#fit-section 앵커**: 병합 섹션에 유지(2026-08-26 기준 저장소 내 사용처 0곳
   — e3c7290에서 소비자가 제거됨. 외부 공유 링크 대비 보존).
4. **GA4**: `apply_cta_click` location `home_bottom` 유지(병합 후에도 홈 최하단
   CTA 의미 동일 — 데이터 연속성). 히어로 버튼 삭제로 `home_hero`는 소멸.

## 되돌릴 조건

모집 시즌 지표에서 홈 진입 → /apply 전환이 유의하게 하락하고, 스크롤 깊이
데이터가 방문자 다수가 4장(Numbers)에 도달하지 못함을 보이면, "성과 선노출"
재상향을 재검토한다. 그 경우에도 peek·배경 체인·앵커 4종 세트를 함께 되돌릴 것.
